## 1. Описание проекта
Liquidity Vault — это учебный проект в сфере децентрализованных финансов (DeFi), разработанный на блокчейне Solana с использованием фреймворка Anchor.

Основная идея проекта — создание программного хранилища, в которое пользователи смогут вносить токены, а взамен получать share-токены, подтверждающие их долю в общем хранилище.

На восьмой неделе реализован базовый каркас Vault. Созданы основные структуры аккаунтов и механизмы управления ими с использованием Program Derived Addresses (PDA).

На данном этапе реализованы создание Vault и открытие персональной позиции пользователя. Внесение и вывод токенов предусмотрены на следующих этапах проекта.

## 3. Реализованные функции

### 3.1. Initialize Vault — создание хранилища
Функция `initialize_vault` создаёт основную инфраструктуру Liquidity Vault.

При выполнении функции:

- Создаётся аккаунт `VaultState`.
- Сохраняется публичный адрес администратора.
- Указывается токен, который Vault будет принимать в будущем.
- Создаётся `Share Mint` для выпуска share-токенов.
- Создаётся `Token Vault` для хранения депозитных токенов.
- Начальное значение общей суммы депозитов устанавливается равным нулю.

Право выпуска share-токенов и управления токен-хранилищем закрепляется за PDA программы.

### 3.2. Open User Position — открытие позиции пользователя
Функция `open_position` создаёт отдельную карточку для пользователя.

В карточке сохраняются:

- Публичный адрес пользователя.
- Адрес Vault, к которому относится позиция.
- Количество внесённых токенов.
- Значение bump, используемое при вычислении PDA.

На восьмой неделе сумма депозита равна нулю, поскольку функция внесения токенов ещё не реализована.

## 4. Архитектура аккаунтов
Программа использует четыре основных типа аккаунтов.

| Аккаунт | Назначение | Владелец / управление |
|---|---|---|
| VaultState | Хранение настроек Vault и общего учёта | Программа Liquidity Vault |
| Share Mint | Создание share-токенов | SPL Token Program; право выпуска у Vault PDA |
| Token Vault | Хранение депозитных токенов | SPL Token Program; токенами управляет Vault PDA |
| UserPosition | Хранение информации о пользователе и его депозите | Программа Liquidity Vault |

### Схема архитектуры
```text
Liquidity Vault Program
          |
          v
      VaultState
          |
     +----+----+
     |         |
     v         v
 Share Mint  Token Vault
     |
     v
UserPosition
```

`UserPosition` логически связана с Vault, а её PDA вычисляется отдельно для каждого пользователя.

## 5. Использование PDA
PDA (Program Derived Address) — это адрес, который вычисляется на основе идентификатора программы и определённых параметров (seeds).

PDA не имеет приватного ключа. Это позволяет программе управлять токенами по установленным правилам без использования личного ключа администратора.

В проекте используются следующие seeds:

| PDA | Seeds |
|---|---|
| VaultState | `["vault"]` |
| Share Mint | `["share_mint", vault]` |
| Token Vault | `["token_vault", vault]` |
| UserPosition | `["position", vault, user]` |

Такая архитектура позволяет однозначно определить адрес аккаунта пользователя по его публичному ключу и адресу Vault.

# Неделя 9 — Депозит и Share-токены
## Цель работы
Реализовать механизм внесения токенов в Liquidity Vault и выпуска share-токенов, отражающих долю пользователя в общем хранилище.

## Реализованная функциональность
В программу добавлена инструкция `deposit`, которая:

1. Проверяет, что сумма депозита больше нуля.
2. Рассчитывает количество share-токенов пропорционально активам Vault.
3. Переводит токены пользователя в Token Vault через CPI.
4. Выпускает share-токены с использованием полномочий PDA.
5. Обновляет данные VaultState и UserPosition.

## Расчёт share-токенов
Первый вкладчик получает share-токены в соотношении 1:1.

Для следующих депозитов используется формула:

**Shares = Deposit × Total Shares / Total Assets**
В тестировании проверен следующий сценарий:

| Действие | Результат |
|---|---|
| Первый депозит | 100 токенов → 100 shares |
| Симуляция дохода | +10 токенов в Vault |
| Второй депозит | 11 токенов → 10 shares |
| Итоговый баланс Vault | 121 токен |
| Общее количество shares | 110 |

Увеличение активов было смоделировано выпуском дополнительных тестовых токенов. Реальная интеграция с Raydium на данном этапе не выполнялась.
